# mobilevit — MobileViT v2 졸음 감지

PC 웹캠으로 얼굴을 실시간으로 보고, 졸음이 감지되면 화면 경고와 경고음을 낸다.
모델은 Hugging Face [mosesb/drowsiness-detection-mobileViT-v2](https://huggingface.co/mosesb/drowsiness-detection-mobileViT-v2) (timm `mobilevitv2_200`, Drowsy / Non Drowsy 2클래스)를 그대로 사용한다.
여기에 mediapipe 얼굴 랜드마크로 눈 감음·하품·고개 끄덕임 규칙을 더했다.

## 설치

이 폴더 안에서 실행한다.

```bash
cd mobilevit
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

- Python 3.12, Windows 기준으로 확인했다.
- 라이브러리 버전은 `requirements.txt`에 `==`로 고정되어 있다. 동작을 확인한 버전이므로 임의로 올리지 않는다.
  - OpenCV는 `opencv-contrib-python` 4.x를 쓴다. mediapipe가 `opencv-contrib-python`을 요구하는데, 버전을 고정하지 않으면 OpenCV 5가 설치된다. OpenCV 5와 `opencv-python`을 함께 설치하면 서로 덮어쓰므로 `opencv-python`은 설치하지 않는다.
- `torch`는 CPU 빌드로 설치된다. NVIDIA GPU를 쓰려면 [PyTorch 설치 페이지](https://pytorch.org/get-started/locally/)의 CUDA 설치 명령으로 같은 버전을 설치한다. 현재 코드는 CPU로 추론한다.
- 가중치는 처음 실행할 때 `models/`에 자동으로 다운로드된다. GitHub에는 올리지 않는다.
  - `best_model.pt` (약 70MB): MobileViT v2, Hugging Face
  - `face_landmarker.task` (약 4MB): mediapipe Face Landmarker, Google

## 실행

```bash
python app.py                 # 파일 선택 창에서 영상 선택, 취소하면 웹캠 실시간 감지. q로 종료
python predict.py face.jpg    # 이미지 1장 판정 (모델만)
python test_videos.py ../sleep test_results.csv   # 폴더 안 mp4 전체를 화면 없이 판정해 CSV로 저장
```

## 판정 기준

매 프레임에서 mediapipe Face Landmarker로 얼굴 1개를 찾고, 아래 4가지 중 **하나라도** 해당하면 졸음으로 판정한다.

| 이유 | 기준 |
|---|---|
| `MODEL` | 얼굴을 잘라 MobileViT로 구한 Drowsy 확률의 최근 2초 평균 > 0.7 |
| `EYES` | 눈 감음 점수(`eyeBlink` 양쪽 평균) > 0.5가 1초 이상 이어짐 |
| `YAWN` | 입 벌림 점수(`jawOpen`) > 0.5가 1초 이상 이어짐 |
| `NOD` | 고개 숙임 각도(pitch)가 최근 2초 중 가장 든 자세보다 15° 이상 큼 |

- 졸음이면 화면에 빨간 테두리, `DROWSY! WAKE UP` 문구, 이유를 띄우고 경고음을 1초에 한 번 울린다.
- 얼굴이 검출되지 않으면 기록을 비우므로 경고가 나지 않는다.
- 기준값은 `detector.py` 상단에서 바꾼다.

## 영상 테스트 결과 (2026-10-29)

### 조건

- 데이터: `sleep/` 폴더의 차량 내 운전자 영상 160개(운전자 8명 × 20개, 1280×720, 30fps, 3.7~17.6초, 총 23분)와 라벨(`sleep/TL1/**/label/*.json`). 데이터는 GitHub에 올리지 않는다(`.gitignore`의 `sleep/`).
- 라벨은 영상마다 시나리오 1개(`scene_info.category_name`)다. `졸음운전`을 졸음, 나머지를 졸음 아님으로 보고 평가했다.

  | 라벨 | 영상 | 프레임 라벨의 주요 행동 |
  |---|---|---|
  | 졸음운전 | 80 | 꾸벅꾸벅졸다, 하품, 뺨 때리기·목 만지기 |
  | 음주운전 | 49 | 무언가를 마시다, 몸 못 가누기, 핸들 놓치기·흔들기 |
  | 물건찾기 | 30 | 몸 돌리기, 허리 굽히기, 손 뻗기 |
  | 휴대폰조작 | 1 | 고개 돌리기 |

  - 데이터셋 오류: `TS1/SGA2100304/SGA2100304S0068/` 폴더 안 영상 이름이 `SGA2100304S0069.mp4`다. 폴더 이름대로 `SGA2100304S0068` 라벨(졸음운전)로 평가했다.
  - 정상 운전만 있는 영상은 없다. 오경보는 "다른 이상 행동을 졸음으로 착각한 비율"이다.
- 30fps 영상을 3프레임마다 1장씩(10fps) 판정했다. 영상 안에서 한 번이라도 경고가 나면 그 영상은 "경고"로 셌다.
- 영상별 결과: [`test_results.csv`](test_results.csv). `model`·`eyes`·`yawn`·`nod` 열은 이유별 첫 경고 시각(초)이고, 비어 있으면 그 이유로는 경고가 없었다.

### 요약

| 방식 | 졸음 감지 (80개 중) | 오경보 (80개 중) | 정확도 |
|---|---|---|---|
| 이전: Haar 얼굴 검출 + `MODEL` | 33 (41%) | 31 (39%) | 51% |
| **현재: mediapipe + 4가지 중 하나 (OR)** | **80 (100%)** | **75 (94%)** | 53% |
| `MODEL`만 | 70 (88%) | 71 (89%) | 49% |
| `NOD`만 | 80 (100%) | 50 (62%) | 69% |
| `YAWN`만 | 11 (14%) | 0 (0%) | 57% |
| `EYES`만 | 0 (0%) | 0 (0%) | 50% |

라벨별 경고 비율(현재 방식): 졸음운전 80/80, 음주운전 49/49, 물건찾기 25/30, 휴대폰조작 1/1.

### 해석

- **현재 방식은 졸음을 다 잡지만 다른 행동도 거의 다 졸음으로 판정한다.** 정확도 53%로, 경고가 났다는 사실만으로는 졸음인지 알 수 없다.
- **MobileViT 모델은 졸음과 다른 행동을 구분하지 못한다.** 평균 Drowsy 확률이 졸음운전 0.73, 음주운전 0.83, 물건찾기 0.71이다. 이전 결과(41% 감지, 39% 오경보)도 얼굴 검출이 끊겨 경고가 덜 났을 뿐, 구분 능력이 있었던 것은 아니다.
- 얼굴 검출 비율은 Haar 평균 64%에서 mediapipe 평균 93%로 올랐다(졸음운전 0.70 → 0.95). 검출이 늘자 모델 경고도 함께 늘어 오경보가 커졌다.
- `NOD`는 졸음 영상을 모두 잡지만, 음주운전(몸 못 가누기)과 물건찾기(허리 굽히기)에서도 고개가 크게 숙여져 오경보가 62%다.
- `YAWN`은 오경보가 0이지만 하품이 있는 영상에서만 잡힌다.
- `EYES`는 한 번도 경고하지 않았다. 고개를 숙이면 눈이 잘 보이지 않고 `eyeBlink` 점수가 0.5를 넘는 시간이 짧다. 기준값을 낮춰 볼 여지가 있다.
- 기준값은 이 데이터의 일부 영상(운전자 SGA2100304 등)의 점수를 보고 정했다. 같은 데이터로 평가했으므로 실제 성능보다 좋게 나왔을 수 있다.
- 개선 후보(미적용): `MODEL`을 판정에서 빼기, `NOD`는 짧은 시간 안에 여러 번 끄덕일 때만 경고하기, `EYES` 기준값 낮추기, 정상 운전 영상을 추가해 오경보 측정하기.

## 한계

- 모델 카드에 따르면 연구용 proof-of-concept이다. 실제 안전 장치로 단독 사용하면 안 된다.
- 야간·어두운 조명, 선글라스·모자·손 가림, 정면이 아닌 카메라 각도에서는 정확도가 떨어질 수 있다.
- CPU에서 얼굴 랜드마크와 모델 추론을 합쳐 약 150ms/프레임이라서 FPS가 6 정도로 낮다.
- 영상 파일은 모든 프레임을 추론하므로 실제 속도보다 느리게 재생된다. 판정 시간은 영상 시간 기준이다.
